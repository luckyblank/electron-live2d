# Live2D Companion · Design Notes

## 设计概念

「发光的伙伴控制舱」把设置窗口理解为用户与桌面角色之间的关系界面。角色不是设置项的配图，而是跨越角色、行为、AI、系统四页持续存在的主角；每次配置都会在桌面舞台上获得即时反馈。

## 信息架构

- 角色：伙伴选择、缩放、位置、动作预览与角色档案。
- 行为：陪伴预设、鼠标互动、窗口边界与动作映射。
- AI：伙伴能力摘要、聊天表达、文本模型、语音模型与本地安全配置。
- 系统：窗口行为、主题、动态效果、外部消息、更新与危险操作。
- 原型外壳：单窗交互 / 四屏总览、主题与减弱动态效果。

## 视觉系统

- 玻璃主题从仓库现有冷紫、冰蓝、珍珠白资产提取颜色。
- 治愈主题从仓库现有樱粉、奶白、星黄色资产提取颜色。
- 正文使用 Windows 可读字体，角色名和短标题使用少量楷体制造私人档案感。
- 通过连续分区、细线和层级文字控制信息密度，避免普通 Dashboard 的卡片汤。

## 真实项目来源

- 四个设置页面、窗口尺寸、角色列表、互动预设、气泡样式、AI/TTS 插件、安全凭据、外部消息与更新能力均来自当前仓库。
- Logo、主题图和 DeepSeek 小蓝鲸透明视频来自当前项目资产。

## 原型模拟

- 模型切换、AI 连接测试、语音试听、聊天回复、更新下载、目录打开和恢复默认均为本地模拟。
- API Key 只显示固定脱敏演示值，不读取环境变量。
- 设置状态保存在 `localStorage`，不写入正式应用配置。

## 待补资产

- `mori-suit`、`hiyori`、`mao_pro` 的稳定封面由正式应用运行时写入用户数据目录；独立原型不复制用户私有缓存，因此以明确占位展示。

## 落地建议

如果把本方案实现进正式设置页，优先落地跨页持续的伙伴状态、预设联动说明和 AI 能力摘要；保留当前成熟的 470 × 760 固定窗口、键盘可访问性和 QA 覆盖。

- 2026-09-15 使用 Electron Chromium 隔离环境完成渲染与真实点击验证。
- 470 × 760 设置窗口尺寸正确，应用内容没有横向溢出。
- Logo、主题图片和 DeepSeek 透明 WebM 均成功加载，视频 `readyState = 4`。
- 角色切换、安静陪伴联动、AI 连接测试、气泡切换、聊天发送、语音试听、主题切换、更新模拟、恢复确认、减少动态效果与四屏总览全部通过。
- 控制台错误为 0；最终结构化结果见 `prototype-verification.json`。
