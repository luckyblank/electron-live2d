# 角色互动方式自定义

## 目标

角色互动分成两类并按角色独立保存：桌面上的固定手势允许修改动作和气泡文字，但不能增删触发项；右键“和我互动”允许修改菜单名称、弹出文字和动作，并增加或删除自定义互动。切换角色时，两类配置都会同步切换。

## 默认值

每个角色首次使用时都有以下五项。设置页会同时显示默认名称和默认动作映射；用户未覆盖动作时，继续走已有的角色语义映射和动作兜底链路。

| 默认菜单名称 | 语义键 | 默认动作映射 |
|---|---|---|
| 打个招呼 | `greet` | 问候 / 挥手动作 |
| 摸摸头 | `head` | 摸头动作 |
| 夸夸她 | `praise` | 开心 / 夸奖动作 |
| 投喂点心 | `snack` | 投喂动作 |
| 随机互动 | `random` | 随机选择可用互动 |

五个默认菜单对应的默认弹出文字依次是“你好呀～”“好舒服～”“被夸奖了 ✦”“好吃！”和“来和我玩吧～”。设置页直接显示这些值，用户可以逐项覆盖。

`actionId` 为空表示“按角色默认”。当用户从下拉框选择具体动作后，该互动会直接引用当前角色上报的稳定动作 ID，例如 DeepSeek 视频角色的 `video:写代码.webm`、视频语义组 `interaction:greet`，或 Live2D 角色的 `clip:挥手`。如果模型资源更新后动作 ID 不再存在，菜单会将该项标为“动作不可用”并禁用，设置页仍保留原值供用户重新选择。

### 固定桌面手势

这些触发方式由程序识别，用户不能新增或删除，但可以覆盖动作与气泡文字。未选择具体动作时仍走原有语义动作。

| 触发方式 | 默认气泡文字 | 默认动作映射 |
|---|---|---|
| 单击头部 | 好舒服～ | 摸头动作 |
| 单击身体 | 碰到我啦～ | 点击回应动作 |
| 连续双击 | 被夸奖了 ✦ | 开心 / 夸奖动作 |
| 连续三击 | 最喜欢你啦！ | 兴奋 / 开心动作 |
| 长按头部 | 再摸一下嘛 | 摸头动作 |
| 长按身体 | 让我靠一会儿 | 休息 / 安静动作 |
| 拖拽结束 | 新位置不错 | 拖拽动作 |

DeepSeek 角色当前可用于这些触发方式的相近具体动作包括 `点击回应-开心跃动.webm`、`点击回应-害羞惊讶.webm`、`点击回应-挠痒咯咯笑.webm`、`点击回应-元气挥手.webm`、`原地小憩沉眠.webm` 和 `被鼠标拖拽悬空反馈.webm`。它们全部以具体动作出现在下拉框中，由用户按角色自行选择；程序不强制覆盖默认语义动作。

### AI 回复情绪联动

AI 回复解析出的稳定情绪键会直接路由到对应互动：`happy → praise`、`sad → sad`、`angry → angry`、`surprised → surprised`、`shy → shy`、`confused → curious`、`calm → calm`。`surprised` 和 `shy` 会优先使用各自的独立语义；只有导入模型确实缺少对应资源时，通用兜底才会依次尝试“好奇”或“摸头”等相近动作。内置 Live2D 角色会组合各自档案中校对过的动作与表情，视频角色则播放包含身体、表情和时序的完整反应片段。

部分模型没有独立的惊讶、难过或生气动作资源，档案会使用最接近且已审核的现有动作叠加对应表情；这属于资源能力降级，不会让互动无响应。视频角色没有可与动作分离的表情层，因此不能把完整 WebM 片段描述为独立表情。

## 设置页交互

角色页面的“角色设定”增加第五个“互动方式”页签：

- “桌面手势”固定显示 7 个现有触发项；没有新增、删除和排序入口。
- 每个手势可修改一条最多 80 个字符的气泡文字，也可从当前角色动作列表中覆盖动作。
- 每行右侧“操作”使用电源图标切换启用/禁用；禁用只停止该触发方式，不删除用户填写的文字和动作。
- 手势播放按钮会按当前未保存值直接预览动作与文字。
- “恢复默认”只重置当前角色的手势动作和文字。
- 下方“右键「和我互动」”继续管理可增删的菜单项。

- “显示”控制该项是否出现在右键菜单和托盘菜单。
- 右键互动可拖动排序；显示项始终位于隐藏项之前，取消勾选后会立即移动到隐藏分组，保存后菜单沿用该顺序。
- “菜单名称”最多 24 个字符；默认项下方保留原始默认名称。
- “弹出文字”最多 80 个字符，与菜单名称分开保存；右键触发和预览都会使用当前填写的文字。
- “动作映射”列出当前角色真实可用的动作，并在默认项中明确展示原映射。
- 播放按钮通过正式互动链路立即预览当前行，不要求先保存。
- 默认项不能删除，但可以停用、改名或覆盖动作。
- 自定义项可以新增和删除；新增时优先选取角色的点击回应动作。
- 每个角色最多保存 12 项，避免原生菜单过长。
- “恢复默认”只重置当前角色，不影响其他角色。

## 数据与运行链路

配置保存在 `electron-store` 的 `modelInteractions` 对象中，以模型 ID 分组：

```json
{
  "modelInteractions": {
    "deepseek-pet": [
      {
        "id": "greet",
        "label": "向我挥手",
        "text": "你好，今天也一起加油吧～",
        "actionId": "interaction:greet",
        "enabled": true
      },
      {
        "id": "custom-example",
        "label": "写会儿代码",
        "text": "一起专心写一会儿代码吧。",
        "actionId": "video:写代码.webm",
        "enabled": true
      }
    ]
  }
}
```

固定手势保存在同级的 `modelGestures` 对象中：

```json
{
  "modelGestures": {
    "deepseek-pet": [
      {
        "id": "double-click",
        "text": "你又双击我啦～",
        "actionId": "video:点击回应-开心跃动.webm",
        "enabled": true
      },
      {
        "id": "drag-end",
        "text": "这里就是新位置吗？",
        "actionId": "video:被鼠标拖拽悬空反馈.webm"
      }
    ]
  }
}
```

主进程会补齐没有写入存储的默认项并清理非法字段。菜单触发时只发送经过白名单处理的语义键、动作 ID、显示名称和弹出文字；renderer 从当前模型的动作目录解析 `actionId`，分别调用视频语义动作、Live2D 显式 motion clip 或原生 motion group，并把配置文字交给现有气泡组件显示。具体动作播放失败时仍会回退到该互动原有的语义动作，不会让菜单点击无响应。

## 边界

- 手势触发条件仍由程序固定：首版不允许用户新建触发器、修改点击间隔或编排多个连续动作。
- AI 情绪反馈、鼠标跟随、缩放和空闲状态不纳入手势自定义。
- 自定义互动当前由“菜单名称 + 弹出文字 + 一个动作映射”组成，不增加脚本、条件编排、连续动作或自定义粒子，避免把首版做成行为编辑器。
- 动作列表依赖当前角色完成加载并上报资源；角色尚未准备好时可以查看默认项，但暂时不能新增自定义项。
