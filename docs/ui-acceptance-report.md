## 4. 本轮整改项复验

### UI-B04：目录型 Cubism 3/4 模型被标记可用但无法加载

- 原优先级：**P1 / 模型兼容性**
- 当前状态：**关闭**。
- 复现模型：`models/openSource/openSource/openSource.model3.json`。
- 原始结果：模型发现器标记为 `ready`；renderer 调用 `nextModel.load(fileUrl)` 后，`live2d-renderer` 内部对 `file:` URL 使用 Node `path.dirname/path.join`，依赖路径变为类似 `file:/...` 或 `./file:/...`，最终 `openSource.moc3` 读取失败。
- 对照结果：同一渲染链路加载 `models/hiyori/Hiyori.zip` 成功。
- 修复策略：在加载 `live2d-renderer` 前，为其使用的 `path.dirname/path.join` 增加 URL-aware 分支；普通文件路径保持原逻辑，`file://` 等资源 URL 使用 `URL` API 解析依赖。
- 独立复验：`openSource.model3.json` 返回 `phase=ready`，可见角色边界为 `x=68, y=40, width=264, height=496`；截图中 moc 与纹理完整，控制台不再出现 `./file:/...` 错误。
- 证据：`C:\Users\lucky\AppData\Local\Temp\live2d-directory-model-qa\results.json`。

### UI-D03：AI 插件说明裁切与过度压缩

- 原优先级：**P1 / 视觉与可读性**
- 当前状态：**关闭**。
- 原始证据：每个主题各有 3 个 `.plugin-detail` 的 `scrollHeight > clientHeight`；截图中正文过小、被裁切，并与状态徽标争抢空间。
- 修复策略：取消 `.plugin-detail` 的 line-clamp/overflow 裁切，让插件卡片自适应增高并由设置页纵向滚动承载。
- 独立复验：glass 三段详情为 `25/25、25/25、37/37`（scrollHeight/clientHeight）；healing 同样为 `25/25、25/25、37/37`，宽度也完全相等，无裁切。两张 AI 页截图中正文、徽标和按钮没有重叠；当前唯一裁切项是有意省略的插件目录长路径。
- 可读性说明：最终详情字号为 8.5px，仍偏紧凑，但已经达到当前 470px 小窗稿的完整语义与无裁切门槛；后续若进一步提升无障碍，应把正文提升到至少 10–11px，并继续允许页面滚动。

## 7. 仍需人工实机关闭的风险

### UI-B02：桌宠原生窗口是否真实移动

旧验收曾观察到 renderer 已识别拖动并显示反馈，但 BrowserWindow 截图原点不变。当前代码增加了 renderer 上报屏幕坐标与系统光标的兼容逻辑，但本任务现有 UI 自动化接口没有原生 Windows 应用表面，无法独立重做物理输入。

签字前必须用物理鼠标完成：

1. 慢拖 5 次；
2. 快拖 5 次；
3. 越出窗口后松手 5 次；
4. 每次确认窗口实际位置改变、松手后不漂移；
5. 重启应用，确认位置已保存；
6. 设置页同时打开，确认动态背景不消失。

### UI-D02：玻璃主题在真实桌面上的对比度

隔离截图只能证明应用自身图层完整，不能证明叠加在真实壁纸、桌面图标和文字上仍清晰。需要分别放在纯白、纯黑、高纹理且有密集图标的桌面上检查正文、标签、卡片边界和焦点状态。
