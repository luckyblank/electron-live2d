# Live2D 桌面伙伴竞品与企业化评审

评审日期：2026-09-11  
评审对象：当前工作区版本  
结论摘要：产品已经形成“轻量桌宠 + Live2D 角色 + 可插拔文字/语音 AI”的清晰雏形，但现阶段更接近可演示的个人版，而不是可直接销售给企业的产品。最有机会的定位不是与大型本地 AI 伴侣比功能总量，而是把“低打扰、低部署成本、品牌角色可替换、AI 能力可组合”做深。

## 1. 当前产品能力基线

当前代码和界面已经具备以下可销售雏形：

- 透明、置顶、不占任务栏的 400×600 Live2D 桌宠窗口；
- 点击互动、拖动定位、光标跟随、分级空闲状态和性能模式；
- 角色切换、单角色独立缩放和昵称；
- `glass` / `healing` 两套设置与聊天主题；
- DeepSeek 文字对话与智谱 GLM-TTS，文字和语音能力可以分别启用或停用；
- 语音播放驱动 Live2D 口型；
- 对话上下文按角色隔离并持久化到本机应用数据目录；切换或停用文字插件不会丢失角色记忆；
- API Key 支持环境变量或 Electron 系统安全存储；
- 用户模型、插件和 TTS 文件存于应用数据目录，升级不覆盖；
- ZIP 模型导入校验、自动更新、托盘管理。

这些能力组合起来，已经不只是“会动的桌宠”，而是一个可被品牌角色、AI 服务和语音能力复用的桌面交互外壳。

竞品事实依据：

- [Desktop Mate Steam 页面](https://store.steampowered.com/app/3301060/Desktop_Mate/)列出了窗口边缘互动、鼠标互动、角色语音、闹钟、多角色测试功能和游戏联动。
- [VPet 官方 GitHub README](https://github.com/LorisYounger/VPet/blob/main/README.md)说明其免费开源、互动/投喂、创意工坊、主题和代码插件生态。
- [AI Desktop Pet Steam 页面](https://store.steampowered.com/app/4227700)列出了本地对话、STT/TTS、视觉与主动对话、Workshop、离线隐私和多语言能力，同时其最低配置需要 8GB 存储并建议较强 GPU。

- [Open-LLM-VTuber / Desktop-Pet](https://github.com/Grobiks/Desktop-Pet)列出了离线运行、多平台、视觉感知、语音打断、Live2D 表情、主动发言和聊天记录等能力。

## 3. 建议产品定位

建议用一句话统一产品定位：

> 一个低打扰、低部署成本、可替换品牌角色与 AI 能力的 Live2D 桌面伙伴。

这个定位包含四个需要长期守住的产品原则：

1. **低打扰**：默认安静、折叠、不过度抢焦点；主动提醒必须有频率、静默时段和一键停用。
2. **低门槛**：安装即用，角色、聊天和语音应能用向导完成，不要求用户理解模型目录或插件文件结构。
3. **可品牌化**：企业能替换角色、名称、欢迎语、主题、人格、知识入口和更新源，而不用改主程序。
4. **可治理**：AI 供应商、API Key、历史长度、内容策略、数据保存和网络访问边界都能明确配置与审计。

## 4. 企业客户可购买的价值

### 4.1 品牌角色桌面入口

把企业 IP、游戏角色、虚拟员工或活动吉祥物变成长期驻留桌面的互动入口。相较网页浮窗，它更有存在感；相较纯桌宠，它又能承载问答、语音、活动提醒和版本内容更新。

适合：游戏发行、动漫 IP、消费品牌、文旅、校园与展会活动。

### 4.2 员工服务与内部助手

通过企业自有插件接入 FAQ、IT 服务台、HR 制度或知识库，把常见问题入口放到桌面。宠物形态可以降低工具的正式感，但必须保留“关闭、静音、隐私说明、不要主动打扰”的员工控制权。

适合：新员工引导、IT 自助、制度查询、培训提醒、健康休息提醒。

### 4.3 客服与会员陪伴

为高价值会员提供带品牌人格的轻量陪伴，并把对话、TTS、活动提醒和角色内容更新作为会员权益。企业真正购买的不是一个聊天框，而是角色持续触达用户桌面的渠道。

适合：会员制消费品牌、粉丝社区、内容平台、游戏运营。

### 4.4 白标交付底座

当前“模型目录 + 插件目录 + 两类 AI 能力 + 主题”的结构适合继续演进为白标底座。企业版可以按品牌交付角色包、主题包、AI 适配器和更新通道，主程序维持统一版本。

## 5. 企业化缺口与优先级

### P0：商业化之前必须完成

- 明确并取得 Live2D SDK、Cubism Core、内置模型和所有角色素材的发布/商用授权；
- 完成 Windows 代码签名、安装包来源验证、升级包签名和失败回滚；
- 建立隐私政策、数据流说明、第三方 AI 供应商披露、历史与 TTS 文件删除入口；
- 收敛宠物 renderer 的高权限架构：当前为兼容 `live2d-renderer` 使用 `nodeIntegration=true`、`contextIsolation=false`、`sandbox=false`、`webSecurity=false`。代码已经禁止页面导航和新窗口，但这不足以满足企业最小权限要求；应把文件/模型加载迁移到受限 preload/main 或隔离的本地协议，并配置严格 CSP；
- 插件与模型包增加签名、来源信任、权限声明和恶意内容隔离；
- 修复“目录模型被发现为可用、实际加载失败”等基础兼容性问题；
- 完成物理鼠标拖动、浅/深/高纹理桌面可读性和多显示器/DPI 实机验收。

本项目允许用户添加任意数量模型和插件，商业发布很可能触及 Live2D 所称的“Expandable Application”。Live2D 官方说明此类应用在发布前需要审核和专门的 Publication License Agreement，而且这一要求也适用于通常可豁免的小型发布者；B2B2X 用途还要求另行联系确认。因此它不是文档尾部的一句免责声明能覆盖的事项，应在报价和上线计划之前完成法律确认：[Live2D SDK 发布许可](https://www.live2d.com/en/sdk/license/)、[Expandable Applications](https://www.live2d.com/en/sdk/license/expandable/)。

### P1：形成企业试点版本

- 首次启动向导：角色、AI、语音、隐私与主动提醒一次配置完成；
- 管理员策略：允许/禁用的插件、模型、网络域名、历史长度、TTS 保存和自动更新；
- 可观测性：崩溃、模型加载失败、AI 错误和版本分布，默认匿名并允许企业关闭；
- 无障碍：键盘焦点、屏幕阅读器名称、最小字号、对比度、减少动画；
- 品牌配置包：Logo、角色、昵称、主题色、欢迎语、人格和帮助链接；
- MSI/静默安装、代理配置、离线配置导入与企业更新通道。

### P2：扩大竞争力

- 按用户选择开启语音输入，而不是默认常驻麦克风；
- 安全的主动提醒、静默时段、日程或企业事件触发；
- 对话记录查看、清除、导出和按角色管理；
- 角色包/插件包的版本管理与受控分发；
- 多语言 UI 与企业术语包；
- 轻量知识检索插件，并在回答中展示来源和“转人工”入口。

### P3：谨慎评估

- 屏幕视觉、持续监听、情感推断、语音克隆和长期画像；
- 多角色同屏和复杂养成系统；
- 开放式公共插件市场。

这些能力能制造演示亮点，但隐私、审核、性能和支持成本都明显更高，不适合在治理能力成熟前作为企业版卖点。

## 6. 推荐商业包装

| 版本 | 目标客户 | 建议内容 | 计价锚点 |
|---|---|---|---|
| Personal | 个人用户 | 基础桌宠、角色切换、主题、用户自带 AI Key | 免费或低价买断 |
| Creator | IP 方与创作者 | 品牌角色包、主题包、对话人格、语音包、内容更新 | 项目费 + 角色/内容分成 |
| Team | 中小团队 | 白标、内部问答插件、静默部署、策略模板、基础支持 | 按设备或席位订阅 |
| Enterprise | 大型组织 | 私有适配、集中策略、签名包、审计、SLA、专属更新通道 | 年度许可 + 实施服务 |

## 7. 近期路线建议

未来 0–1 个月先完成“可稳定演示”：关闭当前 P1 缺陷、补齐实机验收、删除安装包中的 QA 文件、把首次配置和错误恢复打磨完整。

未来 1–3 个月完成“可试点”：品牌配置包、插件/模型签名、隐私与数据删除、企业部署方式、基础遥测和无障碍。

未来 3–6 个月再选择一条增长路径：若偏 IP 商业化，优先角色内容、活动和付费包；若偏企业助手，优先知识插件、管理员策略、部署和 SLA。不要同时追逐养成游戏、全本地 AI、视觉助手和企业知识库四条路线。

## 8. 最终判断

当前版本最值得保留的不是某个具体模型供应商，而是“桌面角色作为统一交互壳、文字与语音能力可分离替换”的产品结构。它能让企业用自己的 IP 和服务构建桌面入口，同时比全本地 AI 伴侣轻得多。

但在对外宣称“企业级”之前，必须把授权、插件安全、数据治理、签名更新、可部署性和基础兼容性补齐。现阶段建议以品牌演示版或封闭试点出售，不建议直接进入大规模企业部署。
